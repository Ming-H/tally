# DESIGN v0.8 —— 结构路由与归因通道（语义问法收口）

状态：定案 ｜ 日期：2026-11-11 ｜ 前置：DESIGN-v0.7（四支柱）
版本：0.7.0 → 0.8.0 ｜ 消融编号：D27（章节路由）、D28（归因通道）

## 一、动机：语义问法的两处实测断点

v0.7 的词法双轨在数字/口径任务上饱和（D19），但「为什么/怎么样」类
语义问法是明确留白（D19 结语："语义问法或受益，未测"）。2026-11-11
在双语料库（中际旭创+贵州茅台，24 docs / 14,701 chunks）实测三题：

| 问法 | 结果 | trace 揭示 |
|---|---|---|
| 三季度营业收入多少 | ✅ 25,004,800,851.32 元+页引用 | 词法饱和区，无需动 |
| 净利润**为什么**增长 | ⚠️ 只答了数字 71.3亿+90.05% | `memory:hit` 短路——L1 台账数字事实命中即 END，归因叙述没机会上场 |
| 经营情况**怎么样** | ❌ 要点竟是**目录页/审计签署页/备查清单** | summary 意图全文词法散射；目录行本身含「管理层讨论与分析」等关键词，行级打分原理上无法区分目录与正文 |

### 根因

1. **缺结构信号**。年报是章节固定的文档（目录页自带 `第X节 名称…页码`
   映射），但检索与摘要层只有词法分数与页码，没有"这块属于哪一章"。
   v0.7 的 `mda_probe`（关键词找 MD&A 锚页）是补丁式的——它能把 MD&A
   页拉进种子，却拦不住**关键词撞库的目录页**从 `hits`/文档头 12 块
   两条侧路混进要点池。
2. **记忆探针无问题类型判定**。L1 台账的键是 (company, period, metric,
   caliber)，答案模板是「X 为 Y 元（同比 Z%）」——只能回答 **what**。
   归因问句（why）命中同一键时被短路成数字复读，与「读不豁免」公理的
   精神相悖：豁免的不是对账，是**回答完整性**。

### 与业界对照（RAG_Techniques, NirDiamant）

- D27 = Hierarchical Indices 的财报域定制（章节即层级索引）；
- D28 = Adaptive Retrieval 的类型分流细化（问句类型决定路径）。
- 明确不引入：HyDE / cross-encoder / semantic chunking——全部依赖向量
  通道，D19 已实测净负，不逆自己的消融数据。

## 二、D27：章节路由（查询期，零 schema 变更）

### 设计

新增 `tally/graph.py::doc_sections(corpus, doc_id) -> list[tuple[str, int]] | None`：

1. 在文档前 8 页找目录块：文本含 ≥3 个 `第[一二三四五六七八九十百]+节`
   模式命中即认定目录页（巨潮年报惯例；券商研报无目录 → 返回 None 降级）。
2. 逐行解析 `第X节 名称 …… -页码-`（点线可选、页码可带连字符），
   得有序 `[(章节名, 起页)]`；下一节起页即上一节止页（尾节开放）。
3. 结果挂 corpus 级缓存（同 doc 二次查询零成本）。
4. `mda_start(doc_id)`：首个名字匹配 `管理层讨论|经营情况讨论` 的节。

`summarize_doc` 要点池加**页级结构过滤**：

- `mda_seed`（现有 MD&A 锚）与 `seed_hits`（主要会计数据表页）保留；
- 补充池 `hits`（原查询命中）与 `chunks_of(target)`（文档头块）**剔除
  `page < mda_start` 的块**——封面、目录、重要提示、释义、备查文件
  全部在 MD&A 之前，一网打尽，不再靠关键词猜；
- 目录解析失败（None）：保持 v0.7 行为，trace 标 `sections:none`（诚实降级）。

### 为什么查询期而不是摄取期

双语料库已入库 14,701 块，摄取期方案需要重灌或 schema 迁移；查询期方案
零迁移、幂等、对已入库语料即时生效。代价是每 doc 首次查询多一次目录
解析（毫秒级，缓存后归零）。

### 边界

- 附注残渣（如 p117 合并政策句含"实现"加分词混入）**不在本批修**——
  章节过滤解决的是前置章节（结构性垃圾），附注在 MD&A 之后，属打分器
  精度问题，留给后续 RSE（Relevant Segment Extraction）批次。
- 摘要意图之外的路径不挂章节过滤（metric 的期间守卫已够）。

## 三、D28：归因通道（memory_probe 类型守卫）

### 设计

`memory_probe` 头部加问句类型判定：

```
_ASKS_WHY = re.compile(r"为什么|为何|原因|怎么回事|怎么会|归因|驱动")
```

- 命中归因词 → 探针**透传不短路**（trace: `memory:skip(why问句)`），
  走 metric 全链路：`expand_query` 已为归因词注入「主要系/主要由于」
  （ingest.py，v0.6 前已备），归因表块召回无障碍；LLM 模式 generate
  叙述成因、heuristic 模式抽取式带出归因句，出口照旧过 verify 闸门。
- 数字问句（what）行为不变——台账命中照常短路，公理 2「读不豁免」维持。

### 定位

这不是新增记忆功能，是**记忆公理的细化**：L1 缓存的是数字事实，
只对 what 型问题构成完整答案；对 why 型问题只是部分证据——部分
证据不应终止推理。与 DESIGN-v0.7 §7.1 公理 ②「缓存证据不缓存结论」
同源：结论的完整性也属于结论。

## 四、不做（YAGNI）
