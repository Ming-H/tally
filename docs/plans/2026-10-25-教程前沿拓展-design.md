## 决策（与作者对齐，2026-10-25）

1. **放置方式：逐章深化 + 新附录 E**。否决「只加附录」（与章节代码走读脱节）
   与「只逐章」（毕业后缺一张按图索骥的总地图）。
2. **体量分级**：
   - 重点章 **ch05 / ch08 / ch10 / ch11 / ch13** 写完整节《前沿拓展：…》
     （60–120 行），四件套：**谱系叙述 → Tally 代码对照 → 若在 Tally 上继续做 →
     一手出处**；
   - 其余 8 章写 `!!! note "前沿一瞥"` 紧凑框（20–40 行：对照表 + 2–3 出处）。
3. **编号与插入点**：完整节续章号（如 `## 5.7 前沿拓展：…`），原「小结」顺延
   +1；紧凑框不编号，插在最后一个内容节末尾、「小结」之前。
4. 各章「延伸阅读」**追加** 1–3 条与本章新内容匹配的链接，不推翻既有条目。

## 附录 E《业界前沿地图》（`appendix-e-frontier-map.md`，~7KB）

- 定位：毕业后的按图索骥页，非必读正文。
- 五张表：按教程四部分分组（语料工程 / 生成与验证 / Agent 架构 / 评测与可靠性）
  + 收尾表「**业界共识与 Tally 的四个分歧**」（向量默认关 / trend 不进环 /
  judge 只能否决 / 自主有界——每条带 Tally 实测依据 + 业界出处）。
- 表列统一：Tally 锚点（机制 + 文件）→ 业界术语 → 一手出处 → 继续做的方向。

## 版式与红线

- admonition（`!!! note`）、「」引号、中文标点，voice 对齐既有章节；不破坏
  每章「失败先行 → 走读 → 小结」节奏。
- **数字纪律**：要么出自 Tally 实测（引 DESIGN/章节原文），要么照抄出处原文
  （如 Contextual Retrieval 5.7%→3.7%→2.9%→1.9%），不编数。
- 出处全部一手核实（与本仓 CLAUDE.md「业界对照」2026-10-25 调研同源；RRF 不在
  arXiv、Contextual BM25 属 2024 原文、Attributed QA 为 2022/arXiv:2212.08037
  三处纠错已吸收）。
- `mkdocs build --strict` 零警告（教程 CI 红线）；`mkdocs.yml` nav 增附录 E；
  教程 README 进度清单加行。
- **Tally 仓库零代码变更**（教程只读锚定，锁定 v0.7+）。
