## 一、动机：病根与处方

**病根**：现教程不缺业界知识（10-25 案已逐章配前沿节），缺的是**组织
单位**——13 章的标题是 Tally 的机制名（「输出验证：覆盖率闸门」），主角
是代码，业界视角只是插入的一节。形态是「开源仓库源码精讲」，不是
「专业教程」。

**处方**：组织单位从「仓库模块」换成「方法问题」。

- 知识谱系升为主角（知识点栏），Tally 降格为实验室（本项目栏）；
- 可迁移性给出口：迁移盒 + 附录 F 设计画布 + 毕业设计；
- 全书给论点：**「你要造的不是模型，是挽具」**——ch01 立论 →
  ch13 harness 工程位 → ch14「harness 是产品」三点连线；
- 教学序 ≠ 运行序（显式处理）：运行时 understand→route 先于检索，教学序
  却把生成/验证（ch06–07）放在理解/路由（ch09）之前——因为 ch06–07 全程
  可零 key 跑（`--mode heuristic`，抽取式生成），ch08 才换 LLM 脑。规则脑
  从「降级兜底」升格为**教学脚手架**。此点在 ch01 阅读路径与第三部开篇
  **双重声明**。

## 五、精确性钉死值（落稿不得偏离）

1. **措辞红线**：全教程禁用「pip install 即跑通」类表述。Tally 未发布
   PyPI、`pyproject.toml` 无 `[build-system]`，flat-layout 下
   `pip install -e .` 会因 auto-discovery 失败。统一口径与 README 30 秒
   流程一致：`git clone` + `pip install -r requirements.txt`。不为教程
   给 Tally 加打包（违反零代码变更红线）。
2. **ch11 注入失败卡 = 注入面地图**，禁用「天然抗注入」一句话结论。
   四层注入面逐一标注「注入能影响什么 / 死在哪道闸」：understand 只见
   query（注入不可达）；grade_docs 见文档（可被带偏 → 失败退规则）；
   generate 见证据（可影响叙述 → 数字闸/方向闸/自检挡）；**主通道 =
   记忆投毒**（语料 → verified_facts → L1 写闸 + 语料指纹失效在防）。
   这是全书最好的失败卡素材，按此写足。
3. **「14 模块」计数口径**：`tally/` 下全部 14 个 `.py`（含 `__init__.py`）。
   以附录 C 生成脚本输出为准；ch01 总图与 ch14 总装走读用同一口径，图注
   注明含 `__init__.py`。
4. **快线构成**：ch01 + ch05 + ch07 + ch11 + ch14（五章保留，但把评测
   换成收口章——快线读者要的是「这本书的主张」，结业论点在 ch14）。
   原案 ch13 换出。阅读路径同时上 `index.md` 首页，不只 ch01。
5. **「三种假绿」定义**（ch13 开篇点名，各配一个现形实验）：
   ① auto 模式静默走 llm 的小模型方差（plain `eval` 默认 auto——用
   `--mode heuristic` 对照现形）；② 记忆命中假绿（eval 默认隔离防——
   `TALLY_EVAL_MEMORY=on` 对比现形）；③ gate ≠ correctness 假绿（闸门
   过了答案未必对——§9 越界样本现形）。
